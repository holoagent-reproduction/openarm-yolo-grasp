# OpenArm 双相机 YOLOE 视觉抓取启动与调试总结

本文记录当前系统的启动顺序、检查方法和本次调试结论。

## 一、网络连接

- Windows 网口：`172.16.13.1/24`
- NUC 网口：`172.16.13.202/24`

Windows PowerShell 连接 NUC：

```powershell
ssh nuc@172.16.13.202
```

密码输入时不会回显字符，这是正常现象。

## 二、启动 MoveIt 并在 Linux 主机显示 RViz

//在 NUC 终端执行：
//（无画面）
//```bash
//source /opt/ros/humble/setup.bash
//source /home/nuc/ros2_ws/install/setup.bash
//~/init_robot.sh
//ros2 launch openarm_bimanual_moveit_config demo.launch.py hardware_type:=real right_can_interface:=can0 left_can_interface:=can1
//```

说明：`init_robot.sh` 初始化真实硬件和控制器；`demo.launch.py` 启动 MoveIt、move_group、控制器和 RViz。

从 Windows 通过 SSH 启动并显示在 NUC 本机屏幕：

```powershell
ssh -t nuc@172.16.13.202 "export DISPLAY=:0; export XAUTHORITY=/home/nuc/.Xauthority; export QT_QPA_PLATFORM=xcb; source /opt/ros/humble/setup.bash; source /home/nuc/ros2_ws/install/setup.bash; ~/init_robot.sh; ros2 launch openarm_bimanual_moveit_config demo.launch.py hardware_type:=real right_can_interface:=can0 left_can_interface:=can1"
```

`DISPLAY=:0` 指向 Linux 本机显示器，`XAUTHORITY` 允许 SSH 启动的程序访问桌面，`QT_QPA_PLATFORM=xcb` 让 RViz 使用 X11 显示。若 `.Xauthority` 无效，在 NUC 执行 `find /run/user/1000 -maxdepth 1 -name '.mutter-Xwaylandauth.*' -print -quit`，再把输出路径设置给 `XAUTHORITY`。

## 三、启动双相机

```bash
source /opt/ros/humble/setup.bash
source /home/nuc/ros2_ws/install/setup.bash
ros2 launch openarm_vision_grasp dual_realsense_grasp.launch.py
```

该启动文件独立启动头部 D435i 和左腕 D415。检查头部图像帧率：

```bash
timeout 5 ros2 topic hz /openarm_vision/head_d435i/color/image_raw
```

检查腕部相机是否与世界坐标系连通：

```bash
timeout 5 ros2 run tf2_ros tf2_echo world left_wrist_d415_color_optical_frame
```

## 五、检查 Windows/WSL2 YOLOE 服务

YOLOE 在 Windows/WSL2 GPU 主机运行，NUC 通过 HTTP 调用。NUC 执行：

```bash
curl --max-time 3 http://172.16.13.1:8765/health
```

正常应包含 `{"ok":true}`。配置地址应为 `http://172.16.13.1:8765/infer`，不要再使用旧 Wi-Fi 地址 `172.16.20.130` 或旧服务地址 `172.16.20.75`。

## 六、构建并启动语义后端

代码或配置更新后：

//```bash
//source /opt/ros/humble/setup.bash
//cd /home/nuc/ros2_ws
//colcon build --packages-select openarm_vision_grasp --symlink-install
//source /home/nuc/ros2_ws/install/setup.bash

启动预览后端：

```bash
source /opt/ros/humble/setup.bash
source /home/nuc/ros2_ws/install/setup.bash
export PYTHONNOUSERSITE=1
nohup ros2 launch openarm_vision_grasp semantic_grasp.launch.py \
  start_cameras:=false \
  show_ui:=false \
  allow_motion:=false \
  > /home/nuc/ros2_ws/semantic_backend.log 2>&1 &
```

`start_cameras=false` 防止重复打开相机；`show_ui=false` 防止重复创建界面；`allow_motion=false` 只规划不运动；`PYTHONNOUSERSITE=1` 避免 NumPy 2 与 ROS/OpenCV 二进制模块冲突。

检查节点是否重复：

```bash
ros2 node list | sort | uniq -c | grep -E 'semantic|yoloe|object_tracker'
```

每个核心节点应只有一个实例。

## 八、预览抓取流程

1. 启动 MoveIt/RViz、双相机、YOLOE 服务、语义后端和语义界面。
2. 输入 `拿起桌子上的水杯`。
3. 确认 `allow_motion=false`，只点击一次“开始识别与规划”。
4. 正常状态为 `detecting → localized → planning → wait_confirm`。
5. 检查目标是否落在杯子主体、三维坐标是否合理、预抓取位姿是否在桌面上方。
6. 预览成功时应出现 `succeeded` 和“预览规划成功，未执行运动”。

查看状态：

```bash
ros2 topic echo /openarm_vision/semantic_status
```

查看三维目标：

```bash
timeout 15 ros2 topic echo --once /openarm_vision/semantic_objects_3d_raw
```

查看二维检测：

```bash
ros2 topic echo --once /openarm_vision/semantic_detections
```

## 十、本次调试遇到的问题与解决方案

### 1. 网络地址变化

最初使用 Wi-Fi 地址 `172.16.20.130`，后来改为网线直连，Windows 为 `172.16.13.1`，NUC 为 `172.16.13.202`。如果只修改 SSH 地址而不修改 YOLOE 配置，能登录 NUC 但语义识别仍会失败。最终统一使用 `ssh nuc@172.16.13.202` 和 `http://172.16.13.1:8765/infer`，并用 `/health` 检查服务。

### 2. PowerShell 端口转发脚本解析错误

原脚本中的反引号、引号和中文编码混用，导致 PowerShell 报“意外的标记”。这是脚本解析错误，不是 ROS 或模型错误。解决方案是重新整理引号和变量表达式，并确认 WSL2 服务监听 `0.0.0.0:8765`。

### 3. NumPy 2 与 ROS/OpenCV 不兼容

语义界面曾报 `module compiled using NumPy 1.x`、`_ARRAY_API not found` 和 `numpy.core.multiarray failed to import`。原因是系统 OpenCV 按 NumPy 1.x 编译，而用户环境优先加载 NumPy 2.x。启动所有 ROS Python 节点前设置 `export PYTHONNOUSERSITE=1`，让 Python 使用系统兼容包。

### 4. 原始相机正常但 YOLOE 叠加图静止

原始图像话题仍有帧，叠加图没有更新，原因包括服务地址仍指向旧 Wi-Fi、没有有效语义查询、或存在重复语义节点。解决方案是先检查 `/health`，再确认 `/openarm_vision/semantic_query` 出现 `active: true`，随后检查 `/openarm_vision/semantic_detections` 和 `/openarm_vision/head_yoloe_overlay`。识别按钮只能点击一次。

### 5. 有二维检测但没有三维定位

曾出现 YOLOE 能输出 `cup` 和掩码，但 `semantic_objects_3d_raw` 没有消息。日志显示 TF 时间外推错误，原因是 HTTP 推理延迟导致检测时间戳比 TF 缓存稍新。三维节点已改为使用明确 ROS 时间，在时间戳超出缓存时使用最新可用 TF，同时保留时间差检查。修复后可以输出 `world` 坐标、尺寸、点数和深度标准差。

### 6. 重复节点导致任务卡住

多次启动后出现两个 `semantic_3d`、两个 `semantic_command`、两个 `semantic_grasp_task` 等。同一任务被多个节点处理，造成反复 `detecting → localized → planning`，最后 `TARGET_NOT_STABLE`。解决方案是停止旧语义进程、清理 ROS 守护进程后只启动一套，并使用实例锁防止重复运行。每次启动后用 `ros2 node list | sort | uniq -c` 检查，每个核心节点必须为 1。

### 7. Python 异步执行错误

真实执行路径曾从 ROS 回调直接创建异步任务，报 `no running event loop`。解决方案是将执行过程包装成同步入口，在需要时用 `asyncio.run(...)` 创建和管理事件循环。

### 8. MoveIt 错误码 -27

语义定位成功但预抓取规划失败，错误码为 `-27`（GOAL_STATE_INVALID）。原因是目标姿态约束过严，直接把物体 yaw 套成末端完整姿态后不可达，且默认末端四元数与当前状态差异过大。已增加位置-only 预览规划，取消强制物体 yaw，并读取当前 `openarm_left_hand_tcp` 的 TF 四元数，只改变位置、保持当前末端方向。之后已经出现 `wait_confirm` 和“预览规划成功，未执行运动”。

### 9. `/joint_states` 和控制器未就绪

启动初期没有 `/joint_states`，并出现 `Could not contact service /controller_manager/list_controllers`。解决方案是先执行 `~/init_robot.sh`，确认 controller manager、joint state broadcaster 和左右轨迹控制器就绪，再启动 MoveIt。最终 `/joint_states` 已恢复约 100 Hz。检查命令：

```bash
timeout 5 ros2 topic hz /joint_states
ros2 topic echo --once /joint_states
```

### 10. 相机 TF 树不连通

MoveIt 曾提示 `world` 与腕部 D415 frame 不在同一棵 TF 树。原因是静态变换发布器使用旧的位置参数。双相机启动文件已改用 `--x --y --z --qx --qy --qz --qw --frame-id --child-frame-id` 长参数，并写入手眼标定结果。用 `tf2_echo world left_wrist_d415_color_optical_frame` 验证。

### 11. RViz 惯量警告

手指 link 的 `unrealistic inertia` 只影响等效惯量盒显示，不代表规划失败，也不是夹爪反向的直接原因。后续若需要，可单独修正 URDF 惯量，不应修改控制链路。

### 12. 夹爪反向和电机发热

调试中出现“命令张开却闭合”和电机明显发热。可能原因是关节正负方向、开度映射、限位或堵转保护错误。已立即关闭 `gripper_motion_enabled`。恢复前必须验证低速单步方向、开度限位、反馈方向、堵转超时、电流和温度保护；不要带电拔插 CAN。确认张开命令确实张开后，才重新接入夹爪执行阶段。

## 十一、从零启动的推荐顺序

1. 接好网线并确认 NUC 为 `172.16.13.202`。
2. 启动 Windows/WSL2 YOLOE 服务，从 NUC 检查 `/health`。
3. 执行 `~/init_robot.sh`。
4. 启动 MoveIt，确认 RViz 显示在 NUC 本机屏幕。
5. 启动双相机，检查图像帧率和 TF。
6. 启动语义后端，保持 `allow_motion:=false`。
7. 启动 Linux 本机语义界面。
8. 检查语义节点均为单实例。
9. 输入“拿起桌子上的水杯”，只做预览。
10. 在夹爪问题解决前，不进入真实夹取。

## 十二、停止程序

```bash
pkill -INT -f 'semantic_grasp.launch.py'
pkill -INT -f 'demo.launch.py'
```

`SIGINT` 请求程序正常退出，优先于强制杀进程。停止真实机械臂前仍要确认机械臂已停稳、夹爪没有继续发热。

夹爪故障修复后，已将新建视觉抓取包中的 `gripper_motion_enabled` 恢复为 `true`，并在 NUC 上重新构建、重启语义后端，当前 `allow_motion=True`。后端核心节点均为单实例。真实抓取仍必须经过“识别稳定 → 预抓取规划成功 → 界面人工确认”三个步骤；不要通过命令行直接提交未经确认的抓取任务。
