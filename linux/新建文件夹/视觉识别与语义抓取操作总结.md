# OpenArm 双相机 YOLOE 视觉识别与语义抓取总结

## 1. 系统目标

当前系统把中文指令转换为受控的视觉抓取任务：

```text
中文指令
  → YOLOE 开放词汇实例分割
  → D435i 深度三维定位
  → 目标跟踪与抓取候选
  → MoveIt 预抓取规划
  → 人工确认
  → D415 腕部复核
  → 接近、夹取、抬升并保持
```

相机分工：

- D435i：头部全局 RGB、对齐深度、目标三维定位；
- D415：左腕近距离 RGB 复核，不使用当前故障的深度模块；
- AprilTag：只用于标定和测量真值，物品本身不贴标签。

首版支持：水杯、马克杯、塑料瓶、易拉罐、纸盒、小盒子。透明杯、玻璃杯、软袋、餐具、线缆和严重反光物体暂不支持。

## 3. Windows 一次性端口转发

WSL2 地址可能在重启后变化。以管理员身份打开 Windows PowerShell，执行：

```powershell
cd E:\Users\lenovo\Desktop\openarm
.\windows_scripts\配置YOLOE端口转发_管理员.ps1
```

第一条命令进入工作目录；第二条自动读取当前 WSL2 地址，并把 Windows `172.16.20.148:8765` 转发到 WSL2。防火墙规则只允许 NUC `172.16.20.130` 访问，不向其他设备开放。

每次 WSL2 地址变化或 NUC 无法连接服务时，重新以管理员身份运行该脚本。

## 4. 启动 YOLOE GPU 服务

在普通 Windows PowerShell 中执行：

```powershell
cd E:\Users\lenovo\Desktop\openarm
.\windows_scripts\启动YOLOE服务.ps1
```

第一条命令进入工作目录；第二条在 WSL2 中激活独立虚拟环境，使用 RTX GPU 加载 YOLOE，并监听 8765 端口。出现以下内容表示服务启动成功：

```text
Application startup complete.
Uvicorn running on http://0.0.0.0:8765
```

这个服务没有图形界面，只负责接收图片并返回类别、置信度、检测框、跟踪 ID 和分割掩码。保持 PowerShell 窗口运行，按 `Ctrl+C` 停止服务。

本机健康检查：

```powershell
curl.exe http://127.0.0.1:8765/health
```

该命令只检查服务、模型和 CUDA 状态，不执行机械臂动作。正常结果包含 `"ok":true`、`"device":"cuda:0"`。

## 6. 启动 ROS 2 安全预览

NUC 终端执行：

```bash
cd /home/nuc/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch openarm_vision_grasp semantic_grasp.launch.py allow_motion:=false show_ui:=false
```

这些命令依次进入工作区、加载 ROS、加载新包，并启动：

- D435i 和 D415；
- YOLOE HTTP 客户端；
- 深度三维融合；
- 目标跟踪；
- `SemanticPick` Action；
- NUC 的 HTTP Skill 服务。

`allow_motion:=false` 明确禁止真实运动。即使界面点击确认，也不会发送机械臂轨迹。

MoveIt 仍使用现有 OpenArm 启动方式独立启动；没有 `/move_action` 时可以看识别结果，但无法完成预抓取规划。

## 7. 在 NUC Linux 显示器打开确认界面

先寻找桌面授权文件：

```bash
ls /run/user/1000/.mutter-Xwaylandauth.*
```

该命令返回当前 Linux 桌面的授权文件。用实际结果替换下面的路径：

```bash
DISPLAY=:0 XAUTHORITY=/run/user/1000/.mutter-Xwaylandauth.实际后缀 QT_QPA_PLATFORM=xcb \
ros2 run openarm_vision_grasp semantic_confirm_ui
```

该命令通过 SSH 发起程序，但界面显示在 NUC 的 Linux 显示器上，而不是 Windows。界面包含：

- 中文指令输入框；
- “仅规划预览”复选框；
- 开始识别与规划；
- 确认执行；
- 取消任务；
- D435i YOLOE 检测叠加画面；
- 当前状态、类别和置信度。

也可以在启动整个系统时直接显示界面：

```bash
DISPLAY=:0 XAUTHORITY=/run/user/1000/.mutter-Xwaylandauth.实际后缀 QT_QPA_PLATFORM=xcb \
ros2 launch openarm_vision_grasp semantic_grasp.launch.py allow_motion:=false show_ui:=true
```

该命令同时启动感知系统和界面，真实运动仍保持关闭。

## 8. 发送中文预览任务

推荐在界面中保持“仅规划预览”勾选，然后输入：

```text
拿起桌子上的水杯
```

也可使用命令发送一次预览任务：

```bash
ros2 topic pub --once /openarm_vision/semantic_goal std_msgs/msg/String \
"{data: '{\"instruction\":\"拿起桌子上的水杯\",\"preview_only\":true}'}"
```

该命令只发送一次语义任务，要求识别和规划预览，不执行机械臂运动。

中文类别映射：

- 水杯、杯子、茶杯 → `cup`；
- 马克杯、带把杯 → `mug`；
- 水瓶、塑料瓶、饮料瓶 → `plastic bottle`；
- 易拉罐、罐子 → `can`；
- 纸盒、饮料盒 → `carton`；
- 小盒子、包装盒 → `small box`。

## 9. 运行状态检查

检查相机图像频率：

```bash
ros2 topic hz /openarm_vision/head_d435i/color/image_raw
ros2 topic hz /openarm_vision/head_d435i/aligned_depth_to_color/image_raw
ros2 topic hz /openarm_vision/left_wrist_d415/color/image_raw
```

三条命令分别检查头部彩色、头部对齐深度和腕部彩色图像频率；每条观察数秒后按 `Ctrl+C`。

检查 YOLOE 检测和叠加画面：

```bash
ros2 topic echo /openarm_vision/semantic_detections
ros2 topic hz /openarm_vision/head_yoloe_overlay
```

第一条显示检测类别、置信度、框、跟踪 ID 和掩码；第二条检查叠加图是否持续发布。

检查三维目标和任务状态：

```bash
ros2 topic echo /openarm_vision/semantic_target
ros2 topic echo /openarm_vision/semantic_task_status
```

第一条显示 `world` 坐标系中的目标中心、尺寸、抓取方向和稳定状态；第二条显示状态机阶段与错误说明。

## 10. 状态机

任务按以下顺序运行：

1. `idle`：等待指令；
2. `detecting`：YOLOE 搜索目标；
3. `localized`：获得稳定三维目标；
4. `planning`：MoveIt 只规划预抓取；
5. `wait_confirm`：界面等待人工确认；
6. `pregrasp`：低速移动到预抓取位姿；
7. `wrist_verify`：D415 复核目标是否在夹爪区域；
8. `approach`：笛卡尔直线接近；
9. `close`：闭合夹爪；
10. `lift`：垂直抬升约 10 cm；
11. `verifying`：综合夹爪、腕部和头部证据；
12. `succeeded` 或 `failed`：结束，不自动执行第二次抓取。

## 11. 真实运动门控

目前严禁把 `allow_motion` 改为 `true`，因为以下条件尚未全部满足：

- D415 腕部标定当前平移 RMS 约 19.5 mm，不满足 `<10 mm`；
- D435i 固定外参尚未完成最终验收；
- `openarm_left_hand_tcp` 朝下抓取姿态尚未通过空载验证；
- `semantic_grasp.yaml` 中三个标定门控仍为 `false`；
- 尚未完成至少 20 次无碰撞空载预演。

真实运动必须同时满足：

1. `head_calibrated: true`；
2. `wrist_calibrated: true`；
3. `tool_orientation_calibrated: true`；
4. 启动参数 `allow_motion:=true`；
5. 界面人工确认；
6. MoveIt、控制器、碰撞环境和急停均正常。

YOLOE、语言解析和视觉结果都不是安全信号。急停、工作区限制、速度限制、碰撞检测和人工确认优先级最高。

## 12. 常见问题

### Uvicorn 启动后为什么没有界面

YOLOE 是纯 HTTP 推理服务，没有图形界面。图像和确认界面由 NUC 的 `semantic_confirm_ui` 显示。

### 界面打开但没有检测画面

依次检查：YOLOE `/health`、NUC 到 Windows 的网络、D435i 图像话题、`semantic_goal` 是否已经发送、`head_yoloe_overlay` 是否有频率。

### NUC 报 NumPy/OpenCV 冲突

新统一启动文件已经自动设置 `PYTHONNOUSERSITE=1`。手工运行相机视觉 Python 节点时也应加入该环境变量。

### D435i 报 IMU/IIO 权限错误

新双相机启动文件已关闭加速度计和陀螺仪，只保留视觉抓取需要的彩色与深度流。不要另外启动会争用同一相机的旧相机节点。

### 找不到 `base_link`

本系统机器人根坐标系是 `world`。三维目标、标定和 MoveIt 约束均应使用 `world`。

### 停止系统

在 ROS 启动终端按一次 `Ctrl+C`，等待两台相机显示 `Close Sensor - Done`；在 YOLOE PowerShell 窗口按 `Ctrl+C` 停止 GPU 服务。不要直接拔相机或强制关闭仍在写入样本的标定进程。
