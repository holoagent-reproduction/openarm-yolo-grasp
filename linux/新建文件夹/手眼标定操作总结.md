# OpenArm 双相机手眼标定操作总结

## 1. 标定目标

本系统包含两种不同的手眼标定关系：

- 左腕 D415：`eye_in_hand`，求 `openarm_left_hand_tcp → D415 彩色光学坐标系`；
- 头部 D435i：`eye_to_hand`，求 `world → D435i 彩色光学坐标系`。

统一使用：

- 机器人根坐标系：`world`；
- 左臂末端坐标系：`openarm_left_hand_tcp`；
- 标定板：AprilTag 36h11；
- 质量门槛：平移 RMS `< 10 mm`，旋转 RMS `< 3°`。

当前已有的 20 组腕部数据结果约为 `19.5 mm / 2.16°`，旋转合格但平移不合格，不能用于真实抓取。

## 2. 安全要求

1. 急停必须随手可按，机械臂周围不得有人。
2. 第一次只检查相机、标签和 TF，不允许运动。
3. 关节调整使用 MoveIt，速度和加速度均限制为 5%。
4. 单次只调整一个关节，幅度为 `±5°`。
5. 每次移动前确认目标姿态不会碰到桌面、相机线缆或机器人本体。
6. 标签丢失、TF 缺失或规划失败时不记录样本。

## 3. 登录并加载 ROS 环境

在 Windows PowerShell 中执行：

```powershell
ssh nuc@172.16.20.130
```

该命令通过 SSH 登录 NUC，提示密码时输入 `1`。

登录后执行：

```bash
cd /home/nuc/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```

三条命令依次进入 ROS 2 工作区、加载 ROS 2 Humble、加载当前工作区中新编译的软件包。每个新终端都要重新执行。

## 4. 启动机械臂和 MoveIt 后进行准入检查

机械臂硬件、控制器和 MoveIt 使用现有 OpenArm 启动方式启动，不修改原启动文件。启动后检查：

```bash
ros2 topic echo /joint_states --once
ros2 action list | grep -E 'move_action|execute_trajectory'
ros2 run tf2_ros tf2_echo world openarm_left_hand_tcp
```

第一条命令读取一次真实关节状态；第二条检查 MoveIt 规划与轨迹执行接口；第三条持续检查 `world → TCP` 变换，看到稳定数据后按 `Ctrl+C` 退出。任一项不存在时不得移动或采样。

## 5. 启动双相机和 AprilTag 检测

终端 A：

```bash
cd /home/nuc/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch openarm_vision_grasp dual_realsense_grasp.launch.py
```

该命令按序列号启动 D435i 和 D415。D435i 发布彩色和深度，D415 当前只发布彩色图。

终端 B：

```bash
cd /home/nuc/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
PYTHONNOUSERSITE=1 ros2 run openarm_vision_grasp tag_detector --ros-args \
  -p cameras_file:=/home/nuc/ros2_ws/src/openarm_vision_grasp/config/cameras.yaml \
  -p objects_file:=/home/nuc/ros2_ws/src/openarm_vision_grasp/config/tag_objects.yaml
```

该命令启动 AprilTag 检测器。`PYTHONNOUSERSITE=1` 强制使用与 ROS OpenCV 兼容的系统 NumPy，不控制机械臂。

检查标签消息：

```bash
ros2 topic echo /openarm_vision/tag_detections
```

该命令持续显示标签 ID、相机角色、相机坐标系位置、旋转和图像时间戳；确认数据稳定后按 `Ctrl+C`。

## 6. 在 NUC 显示器查看相机画面


该命令显示当前图形桌面的授权文件。将返回的真实路径替换到下面的 `XAUTHORITY` 中：

该命令从 SSH 发起窗口，但窗口显示在 NUC 的 Linux 显示器上。腕部标定选择 `/openarm_vision/left_wrist_d415/color/image_raw`，头部标定选择 `/openarm_vision/head_d435i/color/image_raw`。

## 7. 腕部 D415 标定：eye-in-hand

### 7.1 标签布置

将 AprilTag 固定在桌面或独立支架上，整个采样期间标签不得移动。D415 随左臂移动，并始终看到同一标签。

### 7.2 启动同步采样器

```bash
mkdir -p /home/nuc/ros2_ws/calibration_samples
ros2 run openarm_calibration_jog synchronized_sample_node --ros-args \
  -p camera_role:=wrist \
  -p world_frame:=world \
  -p hand_frame:=openarm_left_hand_tcp \
  -p sample_file:=/home/nuc/ros2_ws/calibration_samples/left_wrist_d415_sync.json
```

第一条命令创建样本目录；第二条在 AprilTag 图像时间戳上读取 `world → TCP`，避免机械臂 TF 与图像时间错位，并把腕部样本写入独立 JSON 文件。

### 7.3 启动低速关节点动

```bash
ros2 run openarm_calibration_jog jog_node --ros-args -p allow_motion:=true
```

该命令允许节点通过 MoveIt 以 5% 速度执行单关节 `±5°` 调整。只有机械臂准入检查、急停和现场安全都已确认后才能使用 `true`。

在另一个终端打开点动界面：

```bash
DISPLAY=:0 XAUTHORITY=/run/user/1000/.mutter-Xwaylandauth.实际后缀 QT_QPA_PLATFORM=xcb \
ros2 run openarm_calibration_jog jog_ui
```

该命令在 NUC 显示器上打开 J1–J7 的 `-5°/+5°` 按钮和记录按钮。

也可不用界面，手工发送一次记录命令：

```bash
ros2 topic pub --once /openarm_calibration_jog/command std_msgs/msg/String \
"{data: '{\"command\":\"record\"}'}"
```

该命令只记录一组同步样本，不移动机械臂。

### 7.4 采样原则

- 建议记录 25–35 组，求解器最低要求 12 组；
- 不要只改变一个关节或只做平移；
- 覆盖左右、上下、远近、俯仰、偏航和滚转；
- 相邻姿态至少有约 `2°` 旋转或 `20 mm` 平移差异；
- 每次机械臂完全停止、画面清晰且标签完整可见后再记录；
- 标签应分布在图像中心及四周，但不能贴近画面边缘；
- 避免反光、运动模糊和标签过小。

### 7.5 求解

```bash
PYTHONNOUSERSITE=1 ros2 run openarm_calibration_jog calibration_solver \
  /home/nuc/ros2_ws/calibration_samples/left_wrist_d415_sync.json \
  --mode eye_in_hand \
  --output /home/nuc/ros2_ws/calibration_samples/left_wrist_d415_result.json \
  --max-translation-rms-mm 10 \
  --max-rotation-rms-deg 3
```

该命令使用 `AX=XB` 求出 `TCP → D415 彩色光学坐标系`，自动筛除有限数量的异常样本，并按 `10 mm / 3°` 门槛输出结果。只有结果中的 `accepted: true` 才能进入配置。

## 8. 头部 D435i 标定：eye-to-hand

### 8.1 标签布置

将 AprilTag 刚性固定到左臂 TCP 附近，标签相对 TCP 在整个采样期间不得变化。D435i 固定不动，机械臂带着标签改变姿态。

### 8.2 启动同步采样器

```bash
ros2 run openarm_calibration_jog synchronized_sample_node --ros-args \
  -p camera_role:=head \
  -p world_frame:=world \
  -p hand_frame:=openarm_left_hand_tcp \
  -p sample_file:=/home/nuc/ros2_ws/calibration_samples/head_d435i_sync.json
```

该命令按 D435i 检测时间戳同步记录 `world → TCP` 与 `D435i → Tag`，用于固定相机的 eye-to-hand 求解。

按照腕部相同原则记录 25–35 组多方向姿态，然后求解：

```bash
PYTHONNOUSERSITE=1 ros2 run openarm_calibration_jog calibration_solver \
  /home/nuc/ros2_ws/calibration_samples/head_d435i_sync.json \
  --mode eye_to_hand \
  --output /home/nuc/ros2_ws/calibration_samples/head_d435i_result.json \
  --max-translation-rms-mm 10 \
  --max-rotation-rms-deg 3
```

该命令输出 `world → D435i 彩色光学坐标系`，并附带估计出的 `TCP → Tag` 固定关系。

## 9. 结果写入与坐标系注意事项

标定结果只写入新包：

```text
/home/nuc/ros2_ws/src/openarm_vision_grasp/config/cameras.yaml
/home/nuc/ros2_ws/src/openarm_vision_grasp/config/semantic_grasp.yaml
```

不得修改原 OpenArm、MoveIt 或三相机配置。

注意：求解器输出的是相机“彩色光学坐标系”的变换，而 `cameras.yaml` 的静态发布目标当前是相机安装坐标系 `*_link`。正式写入前必须利用 RealSense 自带的 `link → color_optical_frame` 变换完成坐标合成，不能把光学坐标系结果直接当作安装坐标系结果粘贴。腕部结果以 `openarm_left_hand_tcp` 为父坐标系时，配置中的父坐标系也必须保持一致。

只有完成以下复核后才能把对应的 `calibrated` 和语义安全门控改为 `true`：

1. 求解结果 `accepted: true`；
2. 平移 RMS `< 10 mm`、旋转 RMS `< 3°`；
3. 随机保留姿态复投影/世界位置误差合格；
4. 桌面 5 个实测点三维定位误差 `< 15 mm`；
5. TF 连续稳定，无跳变、环路或重复父坐标系。

## 10. 常见错误

### `base_link passed to lookupTransform ... does not exist`

本机根坐标系是 `world`，不是 `base_link`。统一检查和采样时使用 `world`。

### 标签检测正常但记录失败

检查标签消息是否超过 0.30 秒、`world → openarm_left_hand_tcp` 是否在对应图像时间戳存在，以及相机角色是 `wrist` 还是 `head`。

### 平移误差很大、旋转误差正常

通常是姿态变化不充分、TF/图像时间错位、标签尺寸配置不准确、标签弯曲或只绕单一轴运动。应重新采集，不应手工放宽 10 mm 门槛。

### `NumPy 2.x` 与 OpenCV 冲突

运行标定检测和求解命令时加 `PYTHONNOUSERSITE=1`，使用 ROS Humble 的系统 NumPy。
